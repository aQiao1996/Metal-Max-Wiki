# MM2R 0.99 图片资产规则

本目录只保存权利状态经人工核定的图片资产。`manifest.yaml` 是人工维护的来源与权利清单；`files/` 只允许放入可以在本项目内保存的文件。引用、待授权和已拒绝的项目不得生成本地副本。

## 权利状态

| 状态                | 用途                                               | 是否可保存本地文件                         |
| ------------------- | -------------------------------------------------- | ------------------------------------------ |
| `reusable`          | 具有明确公共许可或作者授权的远程栅格图             | 可以，但必须保留作者、许可和原始来源       |
| `user_capture`      | 用户自有 MM2R 0.99 版本的必要游戏截图              | 可以，需记录版本、地点、触发条件和采集日期 |
| `original_diagram`  | 根据已核对事实重绘的项目原创图表                   | 可以，优先使用 SVG 并声明项目许可          |
| `permission_needed` | 已找到原图，但尚未获得作者授权                     | 不可以                                     |
| `reference_only`    | 仅可作为事实核对或原创重绘的外部参考               | 不可以                                     |
| `rejected`          | 官方攻略本扫描、整套素材、来源不明或版本错误的图片 | 不可以                                     |

## 新增资产

1. 先在 `manifest.yaml` 添加稳定 `id`、类型、准确来源页和原图 URL、作者或站点、许可说明、版本范围、中文替代文本与权利结论。
2. `reusable` 需要能被复查的许可证据，例如原页面的明确许可声明、作者授权记录或可核对的开放许可。清单模型只接受明确的标准许可证、书面授权证据表达或本地原创依据；模型校验只是保守的技术门槛，不能代替人工查看条款、原页面和授权记录。`NOASSERTION`、`unknown`、`N/A`、`TBD`、“授权待定”、“版权所有”和 `All rights reserved` 一类占位语或保留全部权利声明，都不是可复用许可。Creative Commons BY-NC 等明确许可仍可记录为 `reusable`，但站点必须遵守署名、非商业等完整条款。只有“可以查看”、搜索引擎收录或页面没有禁止语句，都不等于授权。
3. 未获得许可时使用 `permission_needed` 或 `reference_only`，并保持 `local_path: null`。授权证据不完整时不得猜测许可名称。
4. 权利与路径审计通过后，才能把允许的图片放入 `files/`。外部图只使用 PNG、JPEG 或 WebP；项目原创示意图可使用 SVG。

`author` 必须是可归属的作者或站点名称。`unknown`、`anonymous`、`N/A`、“作者不明”、“暂无”或纯符号不能充当署名；作者不可考时应暂停本地使用，不猜测归属。

本地路径按 macOS、Linux 和 Windows 的共同安全边界校验：必须位于 `files/` 下，不得使用隐藏路径、百分号编码、控制字符、Windows 设备名、ADS 冒号或可执行文件的伪装双扩展名。路径唯一性同时按 Unicode NFKC 和大小写不敏感规则检查，避免部署后相互覆盖。

下载的 PNG、JPEG 和 WebP 以及本地原创 SVG 都必须写入 `lock.json`。锁定记录的 MIME 类型必须与路径扩展名一致；SVG 只能是无远程最终 URL 的本地原创资产，不得作为 `reusable` 远程图下载。

在 `tools/data-pipeline` 目录执行以下命令：

```bash
uv run mmwiki-data asset-fetch --repo-root ../..
uv run mmwiki-data asset-audit --repo-root ../..
```

`asset-fetch` 只获取 `reusable` 远程栅格图，并为允许的本地图片生成 `lock.json`；`asset-audit` 不联网，核对清单、锁文件、实际内容、权限、目录孤儿，并严格加载五个 `data/interim/mm2r/0.99` 领域文件，验证 `entity_refs` 与 `asset_refs` 双向一致。

清单模型会先拒绝用户信息、片段、IP 字面量、`localhost`、`.local` 和单标签主机名。这只是静态边界；Task 6 的下载器还必须在每一次请求和重定向前重新解析 DNS，并拒绝回环、私网、链路本地和其他非公网地址，避免 DNS rebinding 或重定向绕过。

## 版权与攻略图原则

玩家“为爱发电”不代表作品自动进入公共领域，也不代表作者同意复制、修改或在公开网站再发布。权利不明的玩家攻略图只保留来源链接，不复制像素、字体、装饰或排版。

城镇、迷宫、赏金首、埋藏品和任务位置等复合地图，优先根据已核对事实制作项目原创 SVG。原创图只复用事实关系，不模仿参考图的表达方式，并在清单中保留用于事实核对的参考页。

## 用户自有 0.99 截图

后续截图应来自用户自有的 0.99 版本，仅截取说明中文名、属性、菜单路径或剧情触发点所需的最小画面。文件放入 `files/user-captures/`，清单中使用 `user_capture`，并在 `notes` 记录版本、地点、条件、日期及用户允许。不成批采集剧情或整套游戏素材。

项目原创图放入 `files/original-diagrams/`，清单中使用 `original_diagram`。
